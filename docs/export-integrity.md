# Class 4 — export integrity

The last line of `/export.csv` is `# HMAC-SHA256: <64 hex characters>`.
The MAC covers the exact UTF-8 CSV bytes preceding that line, including the final CRLF.
Verify the original binary file; spreadsheet software may change encoding/newlines and
invalidate the MAC. The footer is metadata, not a student record: remove it only after
successful verification if importing CSV into another tool.

The independent 32-byte `EXPORT_HMAC_KEY_B64` is generated by `scripts/setup_secrets.py`
and supplied to the web container. It is never sent with the export or committed.

```sh
# With an export saved locally:
docker cp grades.csv notesapp-course-web-1:/tmp/grades.csv
docker exec notesapp-course-web-1 python verify_export.py /tmp/grades.csv
```

Exit 0 means valid, 1 means invalid. The verifier has no database import or write path.
An edited grade, newline conversion, truncation, wrong key or trailing data fails validation.
HMAC requires the secret for verification; it authenticates a holder of that secret,
not a unique person. It provides neither confidentiality nor non-repudiation, and an
old valid file can be replayed. A separately authenticated timestamp/version would be
needed for freshness. Public-key signatures would support verification without sharing
this secret; see `labs/class04/integrity_demo.py` for RSA-PSS and the lecture's toy RSA.
